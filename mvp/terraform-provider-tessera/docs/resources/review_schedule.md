# tessera_review_schedule (Resource)

A scheduled access review (a review template): which grants are certified, how long reviewers have, what happens to
undecided items, and when it runs. Needs the operator role with the `tessera:write` scope. The API has no delete route,
so destroying the resource disables the schedule (it stops launching reviews and keeps its history) and removes it from
state.

## Example Usage

```terraform
data "tessera_identities" "controller" {
  query  = "ingrid"
  status = "active"
}

# Certify privileged access every quarter; undecided items go to an escalation reviewer after the due date.
resource "tessera_review_schedule" "privileged_quarterly" {
  name            = "Quarterly privileged access review"
  recurrence      = "quarterly"
  first_run_at    = "2027-01-04T08:00:00Z"
  privileged_only = true
  unused_days     = 45
  duration_days   = 21
  reminder_days   = 5

  close_out              = "escalate"
  escalation_identity_id = data.tessera_identities.controller.identities[0].id
  escalation_days        = 10
}

# Scope a review to one system.
resource "tessera_review_schedule" "aws_annual" {
  name         = "Annual AWS review"
  system       = "aws"
  recurrence   = "annual"
  first_run_at = "2027-03-01T08:00:00Z"
}
```

## Schema

### Required

- `name` (String) 1 to 200 characters, no leading or trailing whitespace.
- `recurrence` (String) `once`, `quarterly`, `semiannual` or `annual`.

### Optional

- `close_out` (String) What happens to undecided items at the due date: `revoke` or `escalate` (needs `escalation_identity_id`). Default `revoke`.
- `duration_days` (Number) Days reviewers have (1 to 90). Default 14.
- `enabled` (Boolean) A disabled schedule launches nothing. Default true.
- `escalation_days` (Number) Days the escalation reviewer has (1 to 30). Default 7.
- `escalation_identity_id` (Number) The id of the active person who decides escalated items (an id from `tessera_identities`).
- `first_run_at` (String) RFC 3339 time of the first run. Required to enable a new schedule. It is sent on create and whenever you change it; the server then moves the run forward on its own, see `next_run_at`. Not read back, and null after an import.
- `privileged_only` (Boolean) Certify privileged access only.
- `reminder_days` (Number) Days before the due date reviewers are reminded (0 up to `duration_days` minus 1). Default 3.
- `review_type` (String) Run the schedule as this review type, whose reviewers and close-out settings then apply. Unset: none.
- `role_ids` (Set of String) Scope the review to the memberships of these business roles. Empty: not scoped by role.
- `system` (String) Review only this connected system's access (as named in the `system` of `tessera_connectors`). Unset: all systems. The server refuses a name that is not one of the tenant's systems.
- `unused_days` (Number) Include access unused for this many days (1 to 365). Default 60.

### Read-Only

- `id` (String) The schedule id (a UUID).
- `next_run_at` (String) When the schedule runs next (null once a `once` schedule has run or while disabled).

## Import

Import is supported using the following syntax:

```shell
#!/bin/sh
# Import by the schedule's id (a UUID; list them with GET /api/v1/reviews/schedules).
# first_run_at is configuration and is not read back, so the first plan after an import shows it as a change to apply.
terraform import tessera_review_schedule.privileged_quarterly 6f1c2d3e-4a5b-4c6d-8e7f-0a1b2c3d4e5f
```
