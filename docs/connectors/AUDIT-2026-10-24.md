# Connection audit, 2026-10-24 (issue #589)

Status: done for template-vs-wizard drift. A review against vendor documentation is still open (#594, #595, #597). Skipped by request: LDAP connect (#590), LDAP/AD provisioning (#591).

Checks per connector: (A) config_fields vs vendor settings, (B) wizard renders every required field,
(C) test/connect and sync covered against a fake server, (D) deletion guard step present.

Server templates (`mvp/server/internal/readiness/templates`): ad, agentcore, awsorg, azurerbac, entra, erp (sap, oracle),
gcpiam, githubscan, google, ldap, okta, pam (cyberark, beyondtrust, delinea), rest_generic, salesforce, scim_app
(slack, zoom, box, dropbox, zendesk, databricks, atlassian, pingone, onelogin, jumpcloud, keycloak, auth0),
sql, successfactors, unixssh, vms (fieldglass, beeline, csvfeed), workday. base.yaml is shared.

Gallery types (GALLERY_META): demo-ad, demo-okta, demo-workday, ad, ldap, entra, okta, google, workday, salesforce,
scim_app, sql, scim:* (12), awsorg, azurerbac, gcpiam, unixssh, githubscan, sap, oracle, cyberark, beyondtrust,
delinea, fieldglass, beeline, csvfeed, agentcore, successfactors, rest_generic.

Method: template config_fields compared with the wizard (`Wizard.tsx`, `governed.ts`, `baseUrl.ts`) and with
`readiness/config.go` validation; connector tests read for a fake server covering connect/probe and sync. Vendor
documentation was not re-fetched in this pass: auth modes, scopes and pagination were checked against what the
connector tests and presets already encode, so a vendor-doc review remains open.

## Results

- Deletion guard (D): present for every connection type. The wizard's `guard` step is generic
  (`SourceDeletionGuard`, kind "connection"), disabled only for a retired connection.
- Fake-server tests (C): every connector package has tests against an in-process fake (httptest, LDAP/SSH servers).
  agentcore has none by design: it reads a recorded snapshot and has no live client (refused in prod).
  demo-* types are simulated.
- Wizard fields (B), gaps found:
  - Workday `api_version`: no input, no validation. Fixed (input and `v44.0` format check, test added). The Workday connector does not read it yet, so calls are not pinned to the version; filed as #597.
  - Entra `hybrid`: no control, so `entra.xlink` could not apply from the UI. Fixed (Yes/No select).
  - AD `use_dirsync`: no control. Fixed (Yes/No select).
  - Google `base_dns` (org units in scope): not renderable or validated. Filed #594.
  - No guard against this drift in general. Filed #595.
- Fields (A): no other missing fields found against the templates. Salesforce API version is an env setting only
  (connector default v61.0), not a connection field; acceptable, noted.
- Skipped by request: LDAP connect (#590), LDAP/AD provisioning (#591).
